## What changed since v1.0.7

### OpenCore 1.0.8
- Boot files, drivers and tools are OpenCore 1.0.8 ([changelog](https://github.com/acidanthera/OpenCorePkg/releases/tag/1.0.8)).
- Every config now carries `HideVerbose = false` on each driver entry. 1.0.8 requires the key; `false` is its failsafe, so nothing boots differently. Because of the new key, these configs no longer validate on OpenCore 1.0.7 or older.
- The Recovery list follows OpenCore 1.0.8's board list. Intel Macs now stop at Tahoe, so Tahoe is offered as **26.7** by number rather than as "latest".

The AppleALC layout list the builder offers is now read from the same release as the kext it ships, so it never offers a layout the kext does not have.

### Builder
- **Haswell laptops** get the cursor patch Dortania gives for display glitches: `framebuffer-patch-enable` and `framebuffer-cursormem = 00009000`.
- **Intel Arc (B580, B570, Pro B60, Pro B50) and NVIDIA Turing or newer** are still reported as unsupported by Apple. Each now also names the third-party driver that runs it ([intel-gpu-macos-driver](https://github.com/yusufklncc/intel-gpu-macos-driver), [NullMoth](https://github.com/nullmoth/nvidia-macos-driver)). Both drivers are experimental, and nothing for them is added to the EFI.
- **en0 / iServices:** run on macOS, the builder checks whether en0 is built-in. If it is not, it adds `built-in = 01` under that device's PciRoot path, as [Dortania's iServices page](https://dortania.github.io/OpenCore-Post-Install/universal/iservices.html#fixing-en0) says to. It declines rather than guesses when en0 is a USB adapter.
- The SSDT step no longer hangs on macOS waiting for a Finder permission prompt.
- On macOS, `diskutil` and `ioreg` are found even when the app starts with a short `PATH`.

### Installing with no network
- A new way onto the stick, from Windows, Linux or macOS: Apple's whole installer plus [UnPlugged](https://github.com/corpnewt/UnPlugged), for a machine with no Wi-Fi or Ethernet macOS can use. The stick is split into FAT32 (OpenCore and the recovery) and ExFAT (the installer).
- Every build Apple still serves for Intel Macs is listed, from High Sierra to Tahoe, older point releases included.
- The installer is downloaded from Apple with [gibMacOS](https://github.com/corpnewt/gibMacOS). It resumes where it stopped, and is checked against the integrity data Apple publishes for it; a damaged 10 MB stretch is fetched again on its own, not the whole package.
- UnPlugged states no licence, so it is not shipped here: it is downloaded from its author at a pinned commit and refused unless its hash matches.
- See [A stick that needs no network](https://yusufklncc.github.io/Hackintosh-for-All-Computers/offline/).

### Community drivers
- One registry for drivers and add-ons nobody here wrote, 26 projects so far: Intel Arc, Intel Xe-LP integrated graphics up to Raptor Lake's UHD 770 (WhateverXe), NVIDIA Turing and newer, RX 9070 and RX 9060 (AMDRadeonRDNA4), Radeon 680M (Radeonized), Radeon 780M, Intel Xe3 (MeowXE3) and Meteor Lake graphics; Realtek, MediaTek MT7925 and MT7902, and Intel BE211 Wi-Fi; AirDrop and Handoff on Realtek, Intel and Broadcom (RTLAirLink, BroadTek, ForbiddenItlwm, WiFiTahoeBridge); sleep, CPU power and fan control add-ons. Device ids are read from each kext's own Info.plist where it names them, and every sentence is the project's own.
- The Machine pane shows the ones that match your hardware in amber, beside Apple's answer and never instead of it. Compatible Hardware lists them in a **Community** tab, one card each, with filters for category, how it goes in, how it was written, and *only what fits this machine*.
- Each card says how the project was made where that can be shown: **AI-written** when it says its code was written with an AI or at least half its recent commits credit one as co-author, **AI-assisted** when some do or the repository carries an AI tool's instructions. The evidence is written beside the label; no label means nothing says either way. The same label is shown when the EFI pane asks whether to add one.
- Each card says who uploaded the release file: a GitHub Actions workflow, or the account it was sent from, and whether GitHub holds a build attestation for that exact file.
- Four of them can go into an EFI: the EFI pane offers them once the build is done, with *no* as the ready answer. A yes downloads the project's release at a recorded hash and applies its own manual steps, quoted as they are applied, then runs `ocvalidate`. All four are experimental by their own account.
- An EFI with community drivers keeps its config as built, as `OC/config-without-community.plist`, and a record of what was added, at which hash. The EFI pane lists them with **Take out**, which puts back everything that driver changed; without the program, renaming one file takes the EFI back.
- **Report how it ran** on each card opens an issue here with the driver, your processor and the device ids it matched filled in, and nothing else about the machine.
- A weekly job checks every project for new releases, lists new projects it has not seen yet for a person to review, and tables the reports of how each one ran.

### Window
- Six panes in the order of the work: **Machine**, **EFI** (was Builder), **USB stick**, then Compatible Hardware, Kexts and About.
- **USB stick** brings Recovery, Installer and the USB stick panes together: pick how macOS gets on (Recovery, No network, Installer image), which macOS, which stick, then one button. The way that fits your machine's network is marked. Recovery downloads straight onto the stick.
- Saving and opening a hardware report is part of the **Machine** pane now. An opened report is the machine the EFI pane builds for and the USB stick pane advises on.
- A turning ring wherever something is being read, so a pane that is waiting no longer looks empty.
- Each pane leads to the next: **Build an EFI for this machine** on the Machine pane, **Put it on a stick** once an EFI is written, and a tick in the sidebar beside each step done.
- The EFI pane draws the hardware as a table rather than console text, keeps each answer given so far as a numbered chip, and ends with what was written, read back from the folder: the SMBIOS, the kexts, the audio layout, SecureBootModel, and what NEXT-STEPS.txt leaves to do by hand.
- The Kexts pane files the 42 kexts under ten groups, each with what its own project says it is for, quoted from its README or GitHub description. A missing licence is marked.
- One style for every secondary button; a desktop is drawn as a desktop on the Machine pane; the Compatible Hardware filters say what they filter; the USB stick pane keeps its button at the bottom.
- The console's colours in the EFI pane, and the Machine pane's graphics warning, now show: both were looked up without naming the theme and fell back to nothing.
- The graphics warning on the Machine pane says what Apple has no driver for, names the community driver that runs the card, and is amber rather than red when one does. "No integrated graphics was seen" no longer reads as "has none": it may be off in the firmware, and the warning says what turning it on would be worth.
- An Intel HD audio codec is shown as the display outputs' HDMI/DisplayPort sound rather than "not supported". On boards whose own audio is a USB device (Realtek ALC4080), that device is not read yet.
- An Apple silicon Mac's Machine pane no longer says "Up to" with no version: the recovery board list names Intel Macs only.
- The sidebar's **Update available** follows the last check, so it is gone once the program is current.
- **Updates from inside the program.** It checks once at start (switch it off in About) and, when a newer build is out, installs it: downloaded, checked against the SHA-256 the release lists, swapped in, reopened. Only the program is replaced. This is the last package that has to be downloaded by hand.
- On a Mac, what the program makes now goes to `Documents/Hackintosh EFI Builder` rather than inside the app.
- A question with many answers scrolls inside its panel, so Continue stays on screen ([#104](https://github.com/yusufklncc/Hackintosh-for-All-Computers/issues/104)).
- Compatible Hardware lists 738 devices in this EFI, plus the community tab.
